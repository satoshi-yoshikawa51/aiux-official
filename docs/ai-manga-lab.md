# AI漫画研究所 — 構想メモ v2「キャラ立ち判定」

鳥山明『ヘタッピマンガ研究所』の精神をAI時代にやり直す企画。
v1では「AI編集者」を広く構想したが、**論点をひとつに絞る**：

> **そのキャラは、立っているか。立っていないか。**

これだけを極める。診察室もネーム講評もいったん脇に置く。
一つの問いに答える装置を作り切ったものだけが、次の施設を建てられる。

> ステータス: 構想段階。このメモが正本。v1は git 履歴にある。

---

## 1. なぜこの一点なのか — 三つの世界で同じ現象が起きている

「キャラが立つ」は漫画用語だが、まったく同じ現象が別の世界に二つある。

| 世界 | 立っている状態 | 死んでいる状態 |
|---|---|---|
| 漫画（小池一夫） | キャラが勝手に動き、物語が転がる | 作者が台詞を「書かされている」 |
| UXデザイン | チームが「田中さんならこの機能使わない」と即答できるペルソナ | スライドの中の年齢・年収・趣味リスト。誰も参照しない |
| 思考術（高松智史のリアリティスイッチ） | 抽象論を捨て、具体的な誰かの現実を頭の中で生々しく再生して考えられる | 「30代女性は〜」で止まる空中戦 |

三つに共通する本質はこれだと考える：

> **キャラが立っている ＝ そのキャラを頭の中で走らせて、
> 未知の状況での行動を即答できる状態（シミュレーション可能性）。**

小池一夫の「キャラが立てば物語は勝手に動く」も、
使えるペルソナの条件も、リアリティスイッチが「入る」感覚も、
全部このシミュレーション可能性の話をしている。
だから**「立ってるか？」を測れる装置は、漫画・UX・ビジネス思考の
三つの市場で同時に意味を持つ**。ここが世界を変えるレバレッジ。

## 2. 発明のコア：キャラのチューリングテスト

「立ってる／立ってない」は今まで、編集者の目利きという暗黙知だった。
これを**測定可能**にする。チューリングテストが「機械は人間に見えるか」を
測ったように、こちらは**「この架空の人物は、人間として振る舞い切れるか」**を測る。

判定は三層。上から順に軽い。

### 判定A：作者問診（即答テスト）

AIが未知の状況を次々ぶつけ、**作者が**即答する。AIは答えを作らない。

```
AI: このキャラ、コンビニのレジ横募金に小銭を入れますか？
AI: 終電を逃しました。タクシー・漫喫・歩き、どれを選びますか？
AI: 一番会いたくない人物から電話です。出ますか？
```

測るのは4つ：

1. **即答性** — 答えに詰まる＝頭の中でキャラが走っていない
2. **具体性** — 「入れると思う」は死。「入れないが、入れない自分に一瞬引け目を感じて視線を逸らす」は生きている
3. **一貫性** — answers同士が同じ核（欠落・価値観）から導出されているか
4. **意外の必然** — 予想外なのに「ああ、このキャラならそうだ」と腑に落ちるか。ステレオタイプは意外性ゼロ、破綻キャラは必然性ゼロ。立つキャラだけが両立する

### 判定B：分離シミュレーション一致率

キャラシートだけを渡された**複数の独立したAI**に、同じ未知状況を答えさせる。

- 各AIの答えがバラバラ → シートは人物を規定できていない（**立っていない**）
- 高い一致＋高い具体性 → シートが一人の人間をピン留めしている（**立っている**）

「作者の脳内にしかない補完」を切り離して、**シート自体の強度**を測れるのが肝。
UXペルソナ判定ではここが主役になる（ペルソナは作者の脳内補完に頼れない。
チーム全員のシミュレーションが一致しなければ道具として死んでいるので）。

### 判定C：ステレオタイプ差分（立ち度スコア）

シートを渡さない素のAIに、属性だけ（「ツンデレの女子高生」「30代共働きの母」）で
同じ質問に答えさせ、判定Bの結果と比較する。

> **立ち度 ＝ シートありの回答 − 属性だけのステレオタイプ回答 の差分**

差分がなければ、そのキャラシートは何文字あってもテンプレの言い換えにすぎない。
「あなたのペルソナ、AIが属性から想像するのと同じでした」は、
UX業界のペルソナの大半に刺さる残酷で有益な宣告になる。

### 出力：立ちカルテ

3判定をまとめた診断書。レーダーではなく**編集者の赤字**の体で返す：

- どの質問でキャラが崩れたか（破綻の現場を引用）
- どこがステレオタイプと不可分だったか
- 何が欠けているか（欠落がない・口癖が機能していない・関係性が未定義…
  ここで小池一夫のキャラクター論が処方箋として効く）
- シェア用の判定画像（「立ってた」スクショがXでの最強の宣伝）

**設計原則は変わらず：AIは空欄を埋めない。** 診断と処方箋の提示まで。
書き直すのは人間。

## 3. 同じエンジン、三つの入り口

| 入り口 | 持ち込むもの | 刺さる相手 |
|---|---|---|
| 漫画・小説 | キャラ設定・キャラシート | 描き手。ヘタッピ〜の系譜 |
| UXペルソナ | ペルソナドキュメント | プロダクトチーム。「うちのペルソナ、立ってる？」を四半期ごとに健診 |
| 思考トレーニング | 顧客像・上司・商談相手 | リアリティスイッチを鍛えたいビジネスパーソン。「解像度が高い」の実測版 |

エンジン（判定A/B/C）は完全に共通。プロンプトの衣替えだけで市場が三つになる。
漫画で研ぎ、UXで稼ぎ、思考術で広がる、という順序を想定。

## 4. 実装計画

### Phase 0 — 公開実験とnote記事（第1回研究報告）

- 自分の既存キャラ（4コマの登場人物）と、**わざと作ったテンプレキャラ**の
  2体を判定にかけ、立ち度スコアに差が出るかを検証する。
  **差が出なければ測定方法を作り直す。ここがこの企画の唯一の技術リスク。**
- 記事：**「あなたのキャラは、チューリングテストに合格するか」**。
  判定の現場を全文見せる（ヘタッピ方式）。
- 続編でUXペルソナ版（「そのペルソナ、AIの想像と同じでした」）。
  こちらはバズの主戦場になりうる。

### Phase 1 — 判定機プロトタイプ（`/lab`）

- 技術は既存のAI受付（`src/app/api/uketsuke/route.ts`）パターンの応用：
  Claude直fetch・フォールバック（API不通時は自己問診シートに降格）・
  簡易レートリミット・`<<<KARTE>>>{json}<<<END>>>`マーカー方式
- 判定Bは同一リクエスト内で温度を変えた複数サンプリング＋判定Cの
  ベースライン呼び出し。問診はHaiku、差分評価はSonnet以上を検証
- ページは既存パターン踏襲：`src/app/lab/page.tsx` ＋ `"use client"` の判定UI。
  カルテはインク＋紙のトークンで診断書らしく

### Phase 2 — 判定履歴と健診

- 同一キャラの再判定で立ち度の推移を見せる（描き直し→再診のループが本体験）
- チーム利用（ペルソナ健診）はアカウントとDBが要るので、
  Academyと同じく**別プロジェクトに切り出す**判断ポイント

### 作らないもの

- キャラ・台詞・設定の生成（永久に作らない）
- 総合点1つだけのスコアリング（「82点」は思考を止める。
  カルテは常に「どこで崩れたか」の引用つきで返す）

## 5. リスクと論点

- **測定の妥当性**：立ち度スコアが編集者の目利きと相関しなければただの
  おもちゃ。Phase 0の対照実験（立つキャラ vs テンプレ）を必ず先にやる。
- **スコアの権威化**：「立ち度が低い＝悪いキャラ」ではない
  （記号的キャラが正解の作品もある）。カルテの文面で診断の限界を明示する。
- **名前の扱い**：小池一夫・高松智史・ヘタッピ〜は「系譜・出典」として
  敬意をもって明記し、サービス名や機能名には冠さない。
  リアリティスイッチは高松氏の用語なので、言及時は出典を示す。
- **ペルソナ判定の政治**：他人が作ったペルソナを「立っていない」と宣告する
  道具は社内政治の武器にもなる。文面は「作り直せばここまで行ける」という
  処方箋トーンに倒す。
