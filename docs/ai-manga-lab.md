## 1. 出発点と中心の主張

### ヘタッピマンガ研究所は何だったか

「上手い絵の描き方」の教本ではなく、**プロ（鳥山明）が素人（えんぴつ君）に
伴走してダメ出しする過程そのものを見せた**のが発明だった。
読者は「教材」ではなく「指導の現場」を読んでいた。

### 中心の主張：足りないのは画力ではなく編集者

- 画像生成AIブーム以降、世界中が「絵を描くAI」を作っている。しかし
  漫画家志望者が本当に手に入らないのは画力ではなく、**「それ、面白くないよ」と
  言ってくれる担当編集**である。
- 鳥山明にはマシリト（鳥嶋和彦）がいた。持ち込みに行ける人間は東京近郊の
  ごく一部。漫画家志望は世界に数百万人いるのに、編集者は数百人しかいない。
- **AIに漫画を描かせるのではなく、AIを編集者・塾長にする。**
  人間が描き、AIは一コマも描かない。これはこのサイトの既存方針
  （4コマのネーム・ネタ作りは人間の仕事）と完全に地続きで、
  生成AIへの反感が強い漫画コミュニティに対して**唯一刺さる立ち位置**でもある。

一行で言うと：

> **「編集者の民主化」— 世界中の描き手ひとりひとりに担当編集をつける。**

## 2. 第1弾テーマ：小池一夫メソッド × AI

### なぜ小池一夫か

小池一夫（劇画村塾）のキャラクター論は、AIで再現する題材として特異に向いている。

1. **「漫画はキャラ起てである」** — ストーリーではなくキャラが先。
   キャラが立てば物語は勝手に動く、という明確なドクトリン。
2. **メソッドが構造化されている** — 欠落・過去・矛盾・口癖・関係性など、
   「キャラを立てる」ための問いが体系になっている。つまり
   **対話で聞き出すインタビュー術**であり、LLMの得意領域そのもの。
3. **再現性が実証済み** — 劇画村塾からは高橋留美子・原哲夫・さくまあきら・
   堀井雄二らが出た。「教え方」自体に汎用性があった証明。

### コア体験：キャラ立て診察室

ユーザーが「描きたいキャラのぼんやりしたイメージ」を持って来る。
AIが塾長として**問診**する。生成はしない。聞くだけ。

```
AI: そのキャラ、何が「欠落」していますか？
    強さでも夢でもなく、そのキャラに一生埋まらない穴の話です。
ユーザー: えっと……母親の顔を知らない、とか？
AI: いいですね。ではその欠落は、キャラの「口癖」にどう漏れ出ますか？
```

問診が一巡したら**キャラカルテ**（構造化されたキャラシート）を出力し、
最後に**立ち判定**を返す：

- 「このキャラを知らない人に一言で説明できるか」テスト
- 「主人公を消して脇役だけで1話作れるか」テスト
- 矛盾・欠落・関係性の3軸レーダー

**重要な設計原則：AIはキャラを「作らない」。** 空欄をAIが埋めた瞬間に
このサービスは死ぬ。AIは問い・診断・ダメ出しだけを担当し、
答えは常にユーザーの中から出させる。ここが生成AIツールとの決定的な違い。

## 3. サービス全体像：AI漫画研究所

「診察室」を入り口に、研究所として増築していく。

| 施設（将来構想） | 中身 | 元ネタの系譜 |
|---|---|---|
| キャラ立て診察室 | 上記。第1弾 | 小池一夫 |
| ネーム診察室 | 4コマ/1Pネームを提出→AI編集者が講評。「1コマ目で読者を掴んでいるか」「視線誘導」「オチの落差」 | ヘタッピ〜＋編集者ノウハウ |
| 連載会議シミュレーター | 完成したキャラ＋ネームで模擬連載会議。複数のAI編集者（褒め役・厳しい役・読者代表）が合議 | ジャンプ編集部 |
| 描き手のカルテ棚 | 自分のキャラ・講評履歴が蓄積し、AIが成長を踏まえて指導（「前作の課題だったオチの弱さ、今回は克服してますね」） | 担当編集の継続性 |

### 世界を変えるスケールの絵

- 日本の漫画編集ノウハウは世界最強なのに、**輸出されていない**
  （作品は輸出されるが、編集技術は編集部の中に閉じている）。
- 多言語対応すれば、ジャカルタやラゴスやサンパウロの15歳に
  「日本式の担当編集」がつく。持ち込みの地理的制約が消える。
- 長期的には「AI漫画研究所出身」の描き手が商業デビューすることが
  サービスの実績になる。劇画村塾がそうだったように、**卒業生が広告**。

### 収益の当たり（構想メモ程度）

- 個人：問診1回は無料 → 月額で講評回数・カルテ棚
- 法人：出版社の持ち込み一次講評・新人発掘のスクリーニング
- 教育：専門学校・海外のマンガ教育機関へのカリキュラム提供

## 4. 実装計画（このリポジトリでやる範囲）

### Phase 0 — 研究発表（note記事 ＋ 公開実験）

元々の目的だったnote記事を「第1回研究報告」に格上げする。

- 記事：**「AIはキャラを立てられるか — 小池一夫メソッドをClaudeにやらせてみた」**
  - 自分のキャラ（既存4コマの登場人物でよい）を実際に問診させ、
    ヘタッピ方式で**指導の現場を全文見せる**。ここが記事の本体。
- 記事内から comixai.dev のプロトタイプへ誘導（↓Phase 1）。
  記事が宣伝、サイトが実験場、という既存の回遊構造に乗せる。

### Phase 1 — キャラ立て診察室のプロトタイプ（`/lab`）

技術的には**既存のAI受付（`src/app/api/uketsuke/route.ts`）の応用でほぼ足りる**：

- Claude APIを直接fetch、`ANTHROPIC_API_KEY`未設定・エラー時は
  **静的な問診シート（自分で書き込む版）に降格**するフォールバック
- インスタンス内メモリの簡易レートリミット、往復上限、文字数上限を踏襲
- 問診完了時は `<<<KARTE>>>{json}<<<END>>>` マーカーでキャラカルテJSONを返し、
  クライアントでカルテ風UI（マンガのインク＋紙のデザイントークン）に描画
- カルテは**画像として保存/シェアできる**ようにする（X流入の導線。
  「私のキャラ、立ってた」スクショが最強の宣伝）
- ページ構成は既存パターン踏襲：`src/app/lab/page.tsx`（メタデータ＋JSON-LD）
  ＋ `clinic.tsx`（`"use client"`）

コスト面：問診はHaikuで十分（受付と同じ）。講評系はSonnet以上を検討。

### Phase 2 — ネーム診察室

- 4コマ画像をアップロード → Claudeのvisionで講評
- 既存の4コマ入稿文化（`public/yonkoma/`）と接続：自作4コマを
  診察室に通してから入稿する、という自分自身のワークフローで dogfooding
- ここから先（カルテ棚・アカウント・課金）はVercel＋外部DBが要るので、
  **本体サイトとは別プロジェクトに切り出す**判断ポイント。
  ComixaiAcademyと同じ「別プロジェクト」パターン。

### 作らないもの

- **絵・ネーム・セリフを生成する機能**（方針違反。永久に作らない）
- 宣伝用の別ビルド（Academyの決まりごとと同じ）

## 5. リスクと論点

- **小池一夫の名前の扱い**：メソッド自体は公刊書籍（『人を惹きつける技術』等）で
  公開された一般理論として再構成する。サービス名・機能名に故人の名前を
  冠さない（「小池一夫メソッドAI」とは名乗らない）。記事では出典として明記し
  敬意を払う。ヘタッピ・劇画村塾も同様に「精神的な系譜」として語るに留める。
- **「結局AIかよ」という反感**：AIが描かない・埋めない設計を最初から
  前面に出す。「AIはマシリト側」という一行で説明が通る。
- **講評の品質**：的外れなダメ出しは実物の編集者より害が大きい。
  Phase 0で自分のキャラ相手に問診プロンプトを徹底的に磨いてから公開する。
  プロンプトの出来がサービスの出来。
