# COMIXAI アカデミー — スマホアプリ（Expo / React Native）

[comixai.dev](https://comixai.dev) の学習コンテンツを、**3Dアバターと一緒に学ぶスマホアプリ**にしたもの。

- **アバターを選ぶ** → **職種を選ぶ** → ホーム画面にアバターが常駐
- 職種（営業／マーケ／事務／創作／人事／サポート／企画／経営／情シスの9種＋「あてはまらない」）で、
  レッスンの例とプロンプトが差し替わる
- レッスンをクリアするとバッジが増え、バッジの数で**称号**が上がる
- 記録は端末内（AsyncStorage）だけ。アカウントもサーバーも使わない

Webサイト本体（Next.js）とは**別プロジェクト**。このディレクトリだけで独立して動く。

## 動かす

```bash
cd ComixaiAcademy
npm install
npx expo start
```

- iPhone / Android の **Expo Go** でQRを読むのが一番早い
- 型チェック: `npm run typecheck`

ストアに出す段階になったら EAS Build（`npx eas build`）へ。`app.json` の `ios.bundleIdentifier` / `android.package` は `dev.comixai.academy` を仮置きしてある。

## Vercelでプレビューを公開する

Web版（`expo export --platform web`）を出せるので、**スマホのブラウザで触れるURL**を
Vercelに置ける。サイト本体とは**別のVercelプロジェクト**にする（同じリポジトリでOK）。

1. Vercel で **Add New… → Project** → このリポジトリ（`aiux-official`）を選ぶ
2. **Root Directory を `ComixaiAcademy` に変更する**（ここだけ必須。既定の `./` のままだと
   サイト本体がビルドされてしまう）
3. Framework Preset は **Other**。ビルドコマンドと出力先は `vercel.json` に書いてあるので、
   画面上では何も入力しなくていい
4. **Deploy**

以降、`ComixaiAcademy/` に変更があったpushだけ再ビルドされる（`vercel.json` の `ignoreCommand`）。
サイト本体のプロジェクトはこの `vercel.json` を読まないので、影響しない。

公開されたURLをiPhoneのSafariで開き、共有 → **「ホーム画面に追加」** すると、
アドレスバー無しのアプリとして起動する（`public/index.html` でその設定を入れている）。

### Web版でできること・できないこと

| | Web（Vercelプレビュー） | ネイティブ（Expo Go / ストア） |
| --- | --- | --- |
| 3Dアバター | ◯ WebGLで動く | ◯ |
| 進捗の保存 | ◯ ただしブラウザのlocalStorage（シークレットタブでは消える） | ◯ |
| 触覚フィードバック | ✗（Web では呼ばない） | ◯ |
| ホーム画面アイコン | △ 「ホーム画面に追加」で近いものになる | ◯ |

**あくまで見た目と流れを確認するためのプレビュー**で、配布物はネイティブアプリのほう。

## 見た目のルール

サイト（`src/app/globals.css` と `src/app/ds.tsx`）の「マンガのインク＋紙」を移植しています。
色・線幅・角丸・影のずらし量は `src/theme/index.ts` に集約してあるので、
サイト側を変えたらこちらも同じ値に揃えてください。

- **書体** — 見出し=Zen Kaku Gothic New 900 / 小見出し・ボタン=700 / 本文=400、
  ひとこと=Yusei Magic（手書き風）、キッカーと数字=JetBrains Mono。
  React Native は `fontWeight` で別ファイルの書体を選べないので、
  太さは必ず `fontFamily`（`FONT.display` など）で指定します。
- **ポップシャドウ** — サイトの `box-shadow: 5px 5px 0 ink` にあたるもの。
  RNの `shadow*` はiOS専用でAndroidではぼかし影になってしまうため、
  `<Pop>` が「同じ形のベタ塗りViewを裏にずらして敷く」方式で描いています。
  ボタンは押すと影が1pxに縮んで本体が2px沈みます（サイトと同じ挙動）。
- **スクリーントーン** — `<Panel tone="dots">` / `"lines"` で網点・斜線を敷けます。
  タイル画像は `npm run tones` で再生成できます。
  （ネイティブは `resizeMode="repeat"`、Webはrepeatに未対応なのでCSSに落としています）
- **コマ** — `<Panel number="1" caption="…" tilt={-1}>` でコマ番号・キャプション・傾き。
- **アイコン** — アプリ内の絵文字はすべて `src/components/icons.tsx` のオリジナル（34種）に
  置き換えてある。単色なので、置く場所にあわせて色を渡す（黒地では白抜き、紙の上ではインク）。
  タブは選択中に赤の丸ベタが入る。

### BGM（`src/lib/music.ts` / `assets/music/`）

効果音と違って**合成ではなく、用意した音源（MP3）をループ再生**します。
差し替えは `assets/music/` のファイルを置き換えるだけ。

- **曲は3枠だけ**：`home`（ホーム・タブまわり＝午後のカフェ）／
  `lesson`（レッスン・復習＝アフタヌーンティー）／`game`（ミニゲーム中＝light_song）。
  オープニングや持ち帰りなど、どれでもない場面は home に寄せる
  （細かく分けるほど切り替わりが増えて、曲の切れ目のほうがうるさくなる）
- **曲は「画面」ではなく「場面」に付ける。** 場面を見ているのは
  `_layout.tsx` の `MusicDirector`（routeの先頭で判定）。ミニゲームは
  Modal＝路上に出ないので、`mini-game.tsx` が自分で `game` に替えて、
  閉じるときに `home` へ返す
- **切り替えはフェード**（0.4秒）。ぶつ切りで替えると場面転換のたびに耳が引っかかる
- **効果音とは別のトグル**（せってい）。「正解の音は欲しいが、曲はいらない」は
  普通の要望で、1つのスイッチに束ねるとそのために両方失う
- Webは最初のタップまで自動再生できない。失敗を覚えておいて、
  **次にどこかを触った瞬間に**そっと再開する（`pointerdown` を capture で拾う）
- バックグラウンドでは止める（BGMがポケットの中で鳴り続けるのは事故）

### 効果音（`src/lib/sound.ts` / `tools/build-sounds.mjs`）

触覚（Haptics）は最初から入っているのに、**聴覚だけが空でした**。星が舞っても
タイルが弾けても称号が上がっても無音で、演出のいちばん安い伸びしろがここに
残っていました。

**音は拾ってきません。合成します。**

```bash
npm run sounds   # -> assets/sounds/*.wav（10個・合計183KB）
```

素材を拾うと出どころと商用利用の確認がついて回るうえ、音のトーンがばらばらに
なります。ぜんぶ同じ音源から作れば、アイコンや書体と同じで「同じ手で描いたもの」に
揃います。設計の決めごと：

- **短い。** いちばん長い `rankup` で1.15秒。鳴り終わる前に次の操作が来ると濁る
- **うるさくしない。** ピークを -12dB に揃えてある。**音ごとの音量差が無い**ので、
  どれかだけ大きくて驚くことがない
- **ドレミで揃える。** 正解・クリア・昇格は同じ音階の上行、外したときだけ下行。
  音楽的な統一が「同じアプリの音」を作る
- 矩形波と三角波。きれいなサイン波だと上品すぎて、この絵に合わない

| 音 | 鳴るところ |
|---|---|
| `tap` / `pick` | 押したとき（`useTap` が配る） |
| `right` / `wrong` | クイズとゲームの当たり外れ |
| `start` | ミニゲームのタイルが走り出すとき |
| `clear` (+`star`) | ゲームを通したとき。**★3のときだけ** `star` を重ねる |
| `badge` / `finish` | バッジを取った／レッスンを終えた |
| `rankup` | 称号が上がったとき。ここでしか鳴らない |

**鳴らないことを異常にしません。** 設定・端末・Webの自動再生規制など、鳴らない
理由はいくらでもあります。どれも学習を止める理由ではないので、失敗はすべて黙って
捨てます（触覚と同じ扱い）。

**iOSの消音スイッチには逆らいません。** 電車で開く人がいる学習アプリで、消したのに
鳴るのはただの事故です。せっていの「効果音」で切ることもできます。

**音は `useTap` が配ります。** 押せるものは全部このフックを通っているので、
ここに置けば「一部だけ鳴らない」が起きません（星と触覚と同じ理屈）。

### ゲームの決着に、動きを付ける

もとは**押した瞬間に結果が切り替わるだけ**で、振り分けた・摘発した・積んだ、
という手ごたえがどこにも残りませんでした。題材ごとに別の絵にしてあります。

| ゲーム | 何が起きるか |
|---|---|
| 仕分け | 札が**選んだ箱のほうへ傾きながら落ちていく**。受ける側の箱は持ち上がる。当たりは縁が黄、外れは赤 |
| 検問 | 摘発した行に**斜めの判子**（HIT / MISS）が落ちる |
| 並べる | 積んだ工程が**下から押し上がって**入り、いちばん新しい1枚に判子 |
| つくえ | 埋まり具合の棒が**伸び縮みする**。はみ出した瞬間だけ机が揺れる |
| 組み立て | 選んだ札が**いちど大きくなってから収まる**（はまる感じ） |

**飛んでいるあいだは古い札を出したままにします。** 先に消して次を出すと、
どちらに入れたのかが絵として残りません。着いてから判定を出し、それから次を配ります
（`sort-game.tsx` の `flying`）。飛行中は入力も受け付けません——連打すると
2枚まとめて飛んでしまいます。

**0.3秒。伸ばさないこと。** 6枚さばくあいだずっと待たされることになります。

### 結果画面の締め

- **コース修了** — コースを終えたのに、バッジ1個ぶんの扱いしかありませんでした。
  4本通した重みが1本と同じ見た目では釣り合わないので、判子を落として
  通った本数を並べます
- **連続日数** — 数えているのにホームに小さく出るだけでした。結果に炎で出します。
  **2日以上のときだけ**——毎回出すと数字が景色になります

### 動きの演出（`src/components/motion.tsx`）

サイトの気持ちよさを移したものが揃っています。とくに派手な2つ：

- **星がパッと舞う（`SparkLayer` / `useSparkBurst`）** — サイトの「AI相談」タブが
  引っ込むときのキラキラ（`globals.css` の `uke-twinkle`）と同じ動き。
  ボタンを押すと、**指のところから**黄と赤の星が9つ散ります。

  出るのは `onPress`（指を離したとき）ではなく **`onPressIn`（触れた瞬間）**。
  ふつうのタップでも0.1秒前後あるので、そのぶん丸ごと待たされていました。
  引き換えに、スクロールし始めた指が押せるものの上にあると一度だけ星が出ます
  （RNはまず子に触りを渡し、あとからスクロールが奪うため）。速さを取っています。

  描くのは画面のいちばん上に置いた `SparkLayer`（`src/app/_layout.tsx`）で、
  ボタンは座標を渡すだけです。**ボタンの中で描いてはいけません**。
  レッスンはカードを `key` で作り直しているので、「つぎへ」のように
  押すと自分ごと消えるボタンだと、星まで道連れになって一度も見えません。

  ネイティブの `Modal` は別の窓で根元の層が届かないため、
  ミニゲームは自前の `SparkLayer` を持っています（Contextなので近いほうが勝つ）。

- **押した感じ（`useTap`）** — 沈み・触覚・星をまとめて配るフック。
  **押せるものは全部これを通します**。一部だけ返事があると、
  返事のないものが「効かない」ように見えるからです。

  見た目は `ui.tsx` の2つに揃えます。ベタ影のあるものは `sinkPop`
  （影が0まで潰れて**影のあった位置まで丸ごと落ちる**／地の色が一段濃く／
  わずかに縮む）、影のない平らなものは `sinkFlat`（きゅっと縮む）。
  文字だけの押せるところは `<Tap>` で包めば済みます。

  サイト（`ds.tsx`）は `translate(2px,2px)` ＋影3px→1px ですが、
  スマホは**指がボタンを覆う**のでこれでは見えません。指の外にはみ出す
  縁の動きと色の変化で伝えます。

  また `Pressable` の `pressed` をそのまま使うと、**速く叩いたときに
  沈んだ姿が見えません**（指を離すのが1フレームで、描く前に戻る）。
  `usePressFeel` が最低110msは沈めたままにします。

  **押して気持ちよくしたくないものには星を出しません**（`sparks={false}`）。
  「やめる」「記録をぜんぶ消す」「案内をとばす」がそれです。
  絵巻の送りも、14回押すあいだ星が舞い続けると絵が見えなくなるので外してあります。

- **称号ランクアップ（`src/components/rank-up.tsx`）** — **アプリでいちばん派手な画面**。
  称号が上がったとき、レッスンの結果を読ませる**前に**全画面で割り込みます。

  ベタフラッシュ（白く飛ぶ）→ 集中線 → 「RANK UP」を叩きつける →
  前の称号に赤い取り消し線 → 金のメダルが判子のように落ちてくる（着地で
  画面が揺れ、星を5か所から撒く）→ 称号名 → 先生のひとこと → つづける。

  集中線は線ではなく**中心から外へ広がる三角のベタ**（`react-native-svg`）。
  線で描くと端末によって細りすぎて消えるためで、アイコンと同じ理屈です。

  **置き場所は先に確保します**（`Slot`）。出来事が増えるたびに縦に積むと、
  すでに出ているものが上へずれて、組み上がる画がガタつきます。
  足元の「つづける」も同じ理由で高さだけ先に取ってあります。

  途中で触ったら**最後まで一気に進めます（閉じません）**。ご褒美の画面なので、
  うっかり触って見逃すのがいちばん惜しい。組み上がってからもう一度触ると閉じます。

- **タイルで画面を覆う（`TileIn`）** — ミニゲームに入るときの切り替え。
  四角いタイルが斜めにパパパパッと並んで画面を埋め、埋まってからタイトルが出ます。
  **速さで持たせる演出なので伸ばさないこと**。端から端まで0.5秒ほどで、
  ゆっくりやると「読み込み中」に見えて逆効果になります。
  タイルの色は、覆ったあとに出す地と同じ色にしてください（違うと切り替わりが見えます）。

### 画面の組み立て方（全画面共通）

ホームで決めた作法を、他の画面もそのまま踏襲しています。**新しい画面を足すときも同じ形にすること。**

```tsx
<Screen
  header={<ScreenHead kicker="COURSES" title="まなぶ" progress={…} note={…} />}
  tone="dots">
  <Cassette>{/* この画面でいちばん押してほしいもの */}</Cassette>
  <Panel>{/* 中身 */}</Panel>
</Screen>
```

1. **上は黒ベタの帯**（`Screen header` ＝ `ScreenHead`）。枠もベタ影も付けない。
   ステータスバーのぶんは帯自身が飲み込む。下の黒いタブバーと同じ黒で挟むことで、
   **あいだが「紙」として立つ**。ここを浮いた黒カードにすると、その効きが丸ごと消える
   （一度そうして失敗している）。
   レッスン画面だけは帯を Stack のヘッダー（`src/app/_layout.tsx`）が持つ。
2. **地は網点の紙**（`Screen tone="dots"`）。帯とタブバーには掛からない。
3. **いちばん押してほしいものは黒いカセット**（`<Cassette>` ＝ ほぼ黒の地に白い網点）。
   赤と黄がいちばん強く出るのはこの上なので、**1画面に1つだけ**。
   中の文字とアイコンは白（`C.paper50`）にする。
4. **黄色いピル**（`<Pill label="NEXT" />`）は「次にやること」の印。これも**1画面に1つだけ**。
   2つ出た時点で「次」の意味が消える。せっていのように「次」が無い画面には置かない。
5. **見出しは帯が持つ**。紙の上にページ見出しを置かない（見出しが2つになる）。
   コマの中の小見出しは `F.h1` をそのまま使う。
6. **先へ進むボタンは `Screen footer` で下に貼り付ける**（長い一覧がある画面）。
   一覧の末尾に置くと、スクロールしないと見つからない。相棒えらびで実際に
   「どこで決めるのか分からない」が起きている。`footer` に渡したぶんの高さは
   本文の下に自動で空くので、**いちばん下の項目が帯の裏に隠れることはない**
   （隠れると、その項目が選べないように見える）。

### 「決める口」は、どの画面でも下

上の 6 はレッスン本編にも効かせています。もともとカードの中にボタンを
置いていたので、**本文が短い回ではボタンが画面のまんなかに来て、
下半分が丸ごと空いていました**。親指の届くところに無いのがいちばん効きます。

ミニゲームも同じ形に揃えてあります（`components/games/parts.tsx` の `GameFrame`）。

```tsx
<GameFrame footer={<GameButton label="これで決める" onPress={decide} />}>
  {/* 本文（縦に伸びる。スクロールする） */}
</GameFrame>
```

- 打つゲーム（トークン収め・AIに指示を出す）は前から下に帯を持っていたので、
  残りの5つをそちらに合わせました。
- `TryAgain` は**読ませる札だけ**を描きます。「もう一度」の口は footer 側に置く。
  押すところが本文の途中にあると、外すたびに位置が変わります。
- 仕分けだけ `center` を付けています。見るものが札1枚しか無いので、
  上下まんなかに置くほうが収まる。**一覧が伸びるゲームには付けない**
  （増えるたびに位置が動いて読みにくい）。
- **レッスンの結果画面も同じ**。修了 → バッジ → 称号と縦に伸びるので、
  「次のレッスンへ」が画面の外に出ていました（320×568の端末で実際に外）。
  下の帯に置き、コマの中は NEXT の印と「ホームに戻る」だけにしています。

### 空いている場所には、これから起きることを書く

打つゲーム（トークナイザー／トークン収め／AIに指示を出す）は、
打つまで下半分に何も無い状態でした。黒地なので、ただの空白に見えます。
**そこで何が起きるのかを、起きる場所に先に書いておきます。**

- トークン系 → 「打つと、ここに『AIから見た区切り』が出ます」
- AIに指示を出す → 採点の観点（役割・目的・条件・出力形式）を札で先に見せる

これは空白を埋めるためではありません。**AIに指示を出す回は、
何を見られるか分からないまま書かせると当てにいく遊びになる**ので、
先に言っておく必要がありました。

### レッスンを途中で抜けるときは、一度きく

レッスンの進み具合はどこにも保存していません（修了したときだけ記録する）。
なのに黙って戻れてしまい、**5枚読んだ人が何も残らずに出ていく**ことがありました。

`lesson/[id].tsx` が `navigation.addListener('beforeRemove')` で1回だけ引き止めます。
読み始めたばかり（1枚目）と、もう終えている人（結果画面）は止めません。
ミニゲームの「やめる」も同じ考えで、押すと確認をはさみます。

> Web版では**ブラウザの戻る**を止められません（履歴の巻き戻しは
> React Navigation の手前で起きる）。確かめるときはヘッダーの ← を押すこと。

### クイズは、答えてから解説までに間を置く

押した瞬間に色と記号が同時に差し替わるだけだと、「答えた」手ごたえが
どこにも出ません。`components/quiz.tsx` で時間差を付けてあります。

1. 選んだ行がひと呼吸ふくらむ（すぐ）
2. 外したときは、正解の行が **240ms 遅れて**起き上がる
3. ○× は判子のように出る
4. 解説はそのあとに滑り込む

目線が「選んだ行 → 正解 → 解説」と動くようにするための順番です。
**同時に出すと、自分がどれを選んだのかを見ないまま解説へ流れます。**

### 読み上げと、文字サイズ

- **アイコンは読み上げに出しません**（`components/icons.tsx`）。このアプリの
  アイコンはすべて隣の文字の言い換えで、単独で意味を持つものは置いていません。
  出すと同じことを2回聞かされます。
- **押せるものには `accessibilityRole="button"` と名前・状態を付ける**
  （`Button` / `PressCard` / `GameButton` / クイズの選択肢）。
  クイズは ○× が記号なので、読み上げには「正解」「あなたの答え」と言葉で渡します。
  色と記号だけで正誤を出していると、そこが丸ごと落ちます。
- **進み具合のバーは数で渡す**（`Progress` に `accessibilityValue`）。
- **端末の文字サイズ設定は、本文には効かせます。** 高さを決め打ちしている
  ところが無いので、大きくすればコマごと伸びます。頭打ちにしているのは
  `Pill` と `Badge` の中だけ（`maxFontSizeMultiplier={1.3}`）。
  丸い札の中の2〜3文字が2倍まで伸びると、札が折り返して隣の見出しを押し出します。

### そのほか、同じ流れで直したもの

- **「次」の口を1画面に2つ置かない。** まなぶの先頭にあった「つづき」の
  カセットは外しました。ホームの赤いボタンと行き先が同じで、**同じ画面の
  中に「次」が2つある**状態だったからです。いまは一覧の中の赤いリング
  （`Spotlight name="learn-next"`）が次の1本を指しています。
- **ホームのキャラの背丈を動かさない。** フキダシの実測から高さを引いて
  いるので、セリフが1行増えるたびにキャラが縮んでいました。**出た高さの
  最大**を覚えて下限にすると、1周した時点で止まります（`(tabs)/index.tsx`）。
- **小さい枠ではカメラを引く**（`Avatar3D` の `zoom`）。画角は立ち姿に
  合わせてあるので、laugh や bow のように大きく動くと頭が枠から出ます。
  レッスンと復習は `zoom={1.18}`。ホームは大きく見せたいので既定の1のまま。
- **バッジの画面は、集めたものを先に出す。** 称号の表を上に置いていたので、
  開いた人が最初に見るのが「まだ手に入れていないもの」でした。

### 選ぶ画面で、説明をどこに出すか

一覧の下に説明を出すと、**説明が出たぶんだけ下が伸びて、先へ進むボタンが
画面の外へ押し出される**。「選んだのに進めない」という一番まずい状態になる。
職種えらび（`src/components/role-picker.tsx`）で実際に起きた。

なので**説明はポップアップで出し、決めるのもその中で行う**。一覧の高さは動かず、
読んでから決められる。外側を押せば閉じられるので、読むだけのつもりの人も逃げられる。

ポップアップの決めるボタンの文言は画面ごとに意味が違うので `confirmLabel` で渡す
（オンボーディング＝「この仕事ではじめる」／せってい＝「この仕事にする」）。

色の役割は画面をまたいで固定です。

| 色 | 意味 |
|---|---|
| 赤 | 押せるもの |
| 黄 | 次にやること（1画面に1つ） |
| 黒 | 枠まわり（帯・タブバー・カセット） |
| 紙＋網点 | 地 |
| 白 | コマの中身。**紙にすでに網点が敷いてあるので、コマに `tone="dots"` を重ねない**（地と見分けが付かなくなる）。斜線 `tone="lines"` は別物なので使ってよい |

背の低い画面（`useWindowDimensions().height < 700`）では、`ScreenHead compact` と
`Cassette compact` で余白を詰めて本文に高さを回します。ホームはこれでアバターの取り分を稼いでいます。

### アプリ内のアイコンを描き直すとき

タブでの表示は22px前後しかないので、**PNGにせずSVG（ベクター）で持つ**こと。
この小ささではPNGは@3xでも輪郭が甘くなるうえ、色ごとに書き出しが要る。

小さいサイズの鉄則:

- **線で描かず「ベタのシルエットから穴を抜く」**（`fillRule="evenodd"`）。
  細い線は黒地の上で溶けて消える
- 24×24グリッド。抜き（マンガのベタに入れるハイライト）は最低2単位の幅を取る
- 1アイコンの要素は3つまで
- 抜きを斜めにして中央へ向けると「目」に見えてしまう。文字行のつもりなら水平に置く

歯車や星は目分量だと歪むので、座標を計算して作る。形の定義も確認用の書き出しも
`tools/build-icons.mjs` に集約してある:

```bash
npm run icons:ui     # = node tools/build-icons.mjs
#  -> realsize.png  22pxで実際にラスタライズして8倍に拡大（端末で見える通り）
#  -> sheet.png     22/44/88px＋白抜き／黒版の一覧
#  -> src/components/icon-paths.ts  アプリが読むパスデータ（自動生成）
```

**必ず realsize.png で判断すること。** 大きい絵だけで見ると、端末では潰れている、
ということが起きる。実際、この工程で「本の抜きが目に見える」「スパナが判別できない」
「パレットが顔に見える」を見つけて直している。

パスデータは `icon-paths.ts` に自動生成されるので**手で書き写さない**。
見た目の大きさの差は `src/components/icons.tsx` の `OPTICAL` で微調整する。

アイコンを増やすときは `tools/build-icons.mjs` の `ICONS` に足して再実行すれば、
型（`IconName`）まで通る。

### アプリアイコンと起動画面

ホーム画面に出るアイコンは別のツール。**PNGを手で触らず、ここから全サイズ焼く。**

```bash
npm run icons:app     # = node tools/build-app-icon.mjs
#  -> assets/images/ の6枚 ＋ public/app-icon.png
#  -> tools/.icon-preview/app-icon.png        120px（iPhoneの60pt）で焼いて5倍
#  -> tools/.icon-preview/app-icon-masks.png  Androidの3種のマスク＋起動画面
```

絵は「黄色の地に網点、黒ベタの角帽、赤いキラリ」。形は `tools/build-app-icon.mjs`
の `CAP_BOARD` / `CAP_TASSEL` / `M`（配置の比率）にまとまっている。

書き出し先ごとに約束ごとが違うので、ツール側で吸収してある：

| 出力 | 約束ごと |
| --- | --- |
| `icon.png` (1024) | iOS・ストア用。**透過なし・角丸なし**（iOSが自分で丸める） |
| `android-icon-foreground.png` (512) | 見えるのは**中央66%（72dp/108dp）の円**だけ。`markFitted()` がそこに収まる倍率を計算している |
| `android-icon-background.png` (512) | 黄色＋網点のベタ |
| `android-icon-monochrome.png` (432) | テーマアイコン。システムが色を塗るので**白の形だけ**。キラリは団子に見えるので入れない |
| `splash-icon.png` (512) | 紙色の上に置くので、**タイルごと角丸**で出す。大きさは `app.json` の `imageWidth` |
| `public/app-icon.png` (512) | 「ホーム画面に追加」で出るもの。iOSは透過を黒で合成するので**透過なし** |

**判断は `app-icon.png` の実寸のコマで行う。** ホーム画面では60pt＝120px程度に
しかならない。この工程で「房が板から切り離された棒に見える」「房とアタマが
くっついて潰れる」「Androidのマスクで帽子のフチが欠ける」を見つけて直している。

### アバターが立つ背景（舞台）

ホームのコマには、アバターがそこに立って見えるよう絵を敷いている。
Midjourneyで描いた元画像を `tools/prepare-stage.mjs` で整えたもの。

```
assets/images/_raw/classroom.png   元画像（MJの出力そのまま）
        ↓  npm run stage:prepare
assets/images/stage-classroom.jpg  コマに敷くもの
```

差し替え点は `src/data/stage.ts` の3つだけで、値はツールが出してくれる。

```ts
export const STAGE = require('@/assets/images/stage-classroom.jpg');
export const STAGE_RATIO = 0.8337;   // 絵の 幅÷高さ
export const STAGE_WALL = '#6f5e3a'; // 絵のいちばん上の色
```

#### 「コマを覆う最小の大きさ」で、下端・中央に敷く

コマの高さは端末で大きくぶれる。実測すると**縦横比が 0.67〜1.10**で、
iPhone SEでは**横長**になる。`cover` の中央切りだと、狭い端末で床が
丸ごと消えてキャラが宙に浮く。

そこで `<Panel bg bgRatio bgColor bgHeight>` は「**コマを覆いきる最小の
高さで敷き、下端・中央に揃えて、はみ出しを切る**」。床は必ず残る。

#### 絵は「引き」で、横に広く描く

**同じコマに敷くとき、縦長の絵ほど拡大率が上がる**（幅を埋めるのに
引き伸ばすため）。拡大されるほど窓や黒板が実物より大きく写り、
隣に立つ人はそのぶん小さく見える。実測では、縦長（0.637）の絵だと
iPhone SE3 の教室は 15 Pro より **24%大きく**写っていて、同じキャラが
そのぶん小人に見えていた。

なので **`STAGE_RATIO` は大きい（横に広い）ほうがよい。0.8 以上を目安**に
する。MJには「教室を引きで、窓と黒板が画面の一部に収まる構図」で頼む
（`--ar 3:4` あたり）。ツールが 0.75 を下回ると警告を出す。

なお**背景をキャラに合わせて縮める案は使えない**。コマを覆う大きさを
下回った瞬間、上に `bgColor` のベタ帯が出る（実測で82px＝コマの13%）。
キャラとの縮尺を詰めたいときは、キャラ側の置き場に高さを渡すか
（→ `(tabs)/index.tsx`）、絵をもっと引きで描くかの2つしかない。

#### MJの出力はそのままでは使えない

`low horizon` と書いても、**MJは地平線を絵の真ん中あたりに置く**。
実際に上がってきた絵も地平線58%・床42%だった。床が多いほど、同じ
コマの中で教室が上へ逃げてキャラの立ち位置が決まらない。

`prepare-stage.mjs` が**下（床）を削って地平線を下げる**のはそのため。
いまは12%削っている（地平線58% → 66%）。

あわせて、立ち位置に**やわらかい楕円の影を焼き込む**。3Dのキャラは
影を持たないので、これが無いと床に貼りついて見える。

#### 縮尺は地平線で合わせる（いちばん大事）

**地平線（床の消失点）はカメラの高さにある。だからそこに立つ人の目線は、
必ず地平線と重なる。** ズレたぶんがそのまま「巨人」「小人」として出る。

キャラをコマいっぱいに立てると、目線はコマの上17%に来る。最初に描いた2枚は
地平線が上から53%にあったので、その差がまるごと巨人に見えるぶんになっていた。
背景を拡大して詰めようとすると計算上2.4倍要って、そこまで寄せるとベンチも木も
空も画面から消える（実際に試した）。

なので**絵ごとに地平線の位置を持ち、そこにキャラの目線が乗る大きさで
キャラを描く**（`StageArt.horizon` →`(tabs)/index.tsx` の `stage`）。
実測した比率から、必要なキャンバスの高さは
`地平線のコマ下端からの高さ ÷ 0.877`（キャラはキャンバスの92%、
目線は足元から身長の90%、頭上の余白3.1%）。

**新しく描くときは消失点を画面のちょうど中央に**（`horizon: 0.5`）。
キャラはコマの57%ほどの高さになり、景色と噛み合う。
地平線を持たない絵（素の教室）は今までどおりコマいっぱいに立つ。

#### ぼかしは切ってある（BLUR=0）

もとは sigma 8 で強くぼかしていた。3Dのキャラは固定のカメラで描かれていて、
MJが描いた部屋の遠近とは一致しない。実測したところ、最初の絵の
**地平線はキャラの顎を通っていた**（本来は目の高さに来る）。ズレ自体は
12%ほどだが、背景がくっきりしていると脳が窓や床の大きさとキャラを
比べてしまい、**「小人が立っている」**ように見える——ぼかすと背景が
「遠く」として処理されて、比べるのをやめる。

**引きの構図で描き直してからは地平線が下がり、そのズレが小さくなった。**
ぼかすと絵の作り込みが丸ごと捨てられてしまうので、いまは既定で掛けない。
小人に見える絵が出てきたら、その絵だけ `BLUR=8` で戻す。

明るさと彩度を少し落として、キャラを前に出すのは続けている。

遠近のズレの残りは、ホーム側で `AVATAR_ZOOM`（`src/app/(tabs)/index.tsx`）
を上げて詰めている。3Dのカメラは選択画面と共用なので触らず、
キャンバスだけを大きくして足元を揃えたまま上へはみ出させている。

```bash
npm run stage:prepare -- assets/images/_raw/sakura.jpg        # -> stage-sakura.jpg
npm run stage:prepare -- 元.jpg stage-別名.jpg                 # 出力名を指定する
CROP_BOTTOM=0.16 npm run stage:prepare -- 元.jpg   # 削る量を変える
BLUR=8           npm run stage:prepare -- 元.jpg   # ぼかしを戻す（既定は0）
BRIGHTNESS=0.85  npm run stage:prepare -- 元.jpg   # もっと沈める
SHADOW=0.45      npm run stage:prepare -- 元.jpg   # 影を濃くする
```

出力名は省略すると `stage-<元画像の名前>.jpg` になる。
**この名前がそのまま舞台テーマのIDになる。**

確認は `tools/.icon-preview/stage.png`。実測した3端末のコマの比率で
切って、フキダシとキャラの位置を重ねてある。**いちばん横長の
iPhone SE で床と窓と黒板が残っていれば合格**。

出力はJPEG。透過が要らないので、PNGだと2.4MBのところが**48KB**で済む
（ぼかすと情報量が減るぶん、さらに小さくなる）。

#### 構図の決まりごと

描き直すときは、切られる前提で組む。

| 帯 | 置くもの |
| --- | --- |
| 上 0〜30% | **切られる。かつフキダシが重なる**。何も置かない |
| 30〜50% | 端末によっては切られる。壁だけ |
| 50〜80% | 黒板・窓など「ここがどこか」を語るもの |
| 80〜100% | 床。手前ほど広がる遠近で |
| 中央の下 | キャラの立ち位置。何も置かない |

キャラは黒フチのない3Dで、背景が濃いと溶ける。**彩度も明度差も抑える**こと。

#### Midjourneyのプロンプト

`--ar 9:16` で出す（削ったあとに 0.637 前後になる）。

```
empty modern classroom interior, 3D anime style, stylised Pixar-like render,
warm cream and soft beige palette, large window on the left casting a soft light
beam across a pale wooden floor, dark green chalkboard on the right wall,
camera at standing eye level, extremely low horizon, wall filling the top four
fifths of the frame, wide empty foreground, soft diffused lighting,
gentle depth of field, muted low-contrast colours
--ar 9:16 --style raw --stylize 150 --no people, characters, text, watermark, logo
```

外すと使えない絵になる指定：

- **`--no people, characters`** — 入れないと必ず人が立ち、立ち位置が埋まる
- **`camera at standing eye level`** — 無いと俯瞰になり、キャラが床にめり込む
- **`wide empty foreground`** — 机や椅子が手前に来ると、キャラが物の中に立つ
- **`muted low-contrast`** — 背景が強いとキャラが溶ける

なお `extremely low horizon` を入れても効きは弱い。**削る前提で頼むほうが早い。**

つなぎの絵が要るとき（元画像がまだ無いなど）は `npm run stage` で
`tools/build-stage.mjs` がベクターの教室を描く。

日本語フォントはサブセット化して積んでいます（10.2MB → 2.1MB）。

## オープニング（AIの75年）

初回起動のときだけ `/opening` が出て、サイトの `/history` の年表を1コマずつ見せます。
真ん中に動画、左右に送りの三角、6秒で自動送り、下に**いつでも押せる**「本編にすすむ」。

### 「ダウンロード画面」にはしていない

一度そう作ろうとしてやめました。**ストアから落とした時点で中身は全部端末に入っている**
ので、進捗バーを出しても中身のない演出になります。ソシャゲにあれがあるのは、本体を
薄く出して**インストール後に中身を取りにいっている**からで、あの進捗は本物です。

うちは全部同梱なので、出すなら偽の進捗になる。**AIリテラシーを教えるアプリが、入口で
嘘の進捗を見せるのは筋が通りません。** なのでオープニング演出として作ってあり、
止めない・急かさない・いつでも飛ばせる形にしています。

裏でホームの重いもの（アバターのGLB・舞台）を先読みしていますが、**進捗は出しません**。
見せるほどの待ちではないし、出せばそれこそ演出になります。

### 動画はアプリに積まない

mp4は14本で7MB。**1回しか見ない画面のためにアプリを7MB太らせない**ので、
サイト（`comixai.dev/history/`）から取りにいきます。

- 静止画（webp・14枚で1.2MB）は**アプリに積んである**。これが常に下に敷いてあり、
  動画が届いたら上に重なる
- **電波が悪くても絵巻は成立する**（動きが無いだけ）。止まらない
- 配信元を変えたいときは `EMAKI_ORIGIN=http://localhost:8091 npm run emaki`

動画は **H.264（avc1）**。iOS/Androidともハードウェアで再生できますが、
**headless Chromium は H.264 を持っていない**ので、Playwrightでの自動確認では
静止画のまま映ります（`canPlayType` が空を返す）。動きの確認は実機かデスクトップの
Chrome/Safariでやってください。

**`playsInline` を外さないこと。** iOS Safari は `playsinline` の付いていない
`<video>` を、再生した瞬間に全画面へ持っていきます。コマの中で再生させたいので、
`VideoView` に `playsInline` と `fullscreenOptions={{ enable: false }}` を渡しています
（一度これを忘れて、1コマ進むたびに全画面になりました）。

**`VideoView` は「箱で囲って、中で100%」にすること。** `left/right/top/bottom` だけを
指定しても、react-native-web は `<video>` を素の大きさのまま置いてしまい、コマから
はみ出して下の文章に被ります。外側の `View` で位置と `overflow: 'hidden'` を決め、
`VideoView` 自身は `width: '100%', height: '100%'` にします。

`<Panel bg>` の `Image` でもまったく同じ罠を踏んでいます（`ui.tsx` のコメント参照）。
**react-native-web では、上下左右の指定だけでメディア要素は縮まない**と覚えておくこと。

### 素材の取り込み

コマのデータと絵は自動生成なので、手で編集しない。

```bash
npm run emaki   # サイトの src/app/history/eras.ts から取り込む
```

- `src/data/emaki.ts` … 年・タイトル・本文・ツッコミ・トーン・動画URL（生成物）
- `assets/images/emaki/*.webp` … コマ絵（サイトの public/history からコピー）

2回目以降は出ません（`seenOpening` を保存している）。**記録をリセットしても
出し直しません**——初回だけの導入であって、見返したいものではないため。

## 入口の一幕（相棒が歩いてくる）

職種を決めた直後、`/intro`（`src/app/intro.tsx`）を1枚はさみます。
**網点の紙だけの画面に、右から相棒が歩いてきて、中央で止まり、正面を向いて**
「AIの前に、まずこのアプリの使い方からだ」と言う。タップするとホームへ渡し、
下のチュートリアルに続きます。帯もカードもボタンも置きません——ここは画面ではなく
**間（ま）**なので、要素を足すほど「場面が変わった」感じが薄れます。

**秒数で勝手に送りません。** 読み終わる速さは人によって違うので、速い人は
待たされ、遅い人は読み切る前に消えます。押したら進む、に統一しています。

### 立ち位置はホームに合わせる

次に映るのがホームなので、**同じ大きさの相棒が同じ高さに立っている**必要があります。
ずれていると、切り替わった瞬間にキャラが跳ねて「別の画面」になります。

ホームのアバターは、上下に積まれたものに挟まれて位置が決まります。

```
安全領域 / 黒帯 / 画面の余白 / コマの枠と内余白 / フキダシ / すきま
  ……アバター……
すきま / コマの枠と内余白 / 次のカセット / 画面の余白 / 案内のパネル /
タブバー / 安全領域
```

一幕には**そのどれも無い**ので、同じ大きさ・同じ高さは数字で作ります
（`intro.tsx` の `HOME` / `HOME_EDGE` / `GUIDE_H`）。踏んだ罠が3つあります。

**① 安全領域を引き忘れない。** ノッチのある実機では上下で90pxほど食われます。
Webで見ていると0なので、**枠の幅で頭打ちになっているように見えて、実機では
高さで頭打ちになる**。一度これで実機だけ4割大きくなりました。

**② 案内のパネルのぶんも見込む。** 一幕の次に映るのは「案内が出ているホーム」で、
ホームはパネルのぶんアバターを縮めています（`Screen` の `reserve`）。
見込まないと、切り替わった瞬間にキャラが縮みます。

**③ フキダシは「ホームで出る行」を測る。** アバターの上にどれだけ空くかは
フキダシの行数で決まり、行数は端末の幅で変わります（同じ文でも390では3行、
414では2行）。なので**ホームの1歩目に出る行（`TUTORIAL[0]`）を透明の
フキダシに入れて測り**、その高さで場所を決めています。自分のセリフで測ると
行数が食い違い、実測で10%ずれました。**測るのはホームの行、出すのは自分の行。**

合わせた結果（Web、安全領域0）：

| 画面 | 案内中ホーム | 一幕 | 足元から下まで |
|---|---|---|---|
| 390x844 | 250x276 | 250x275 | どちらも337 |
| 393x852 | 258x284 | 258x284 | どちらも337 |
| 414x896 | 322x355 | 322x354 | どちらも337 |
| 430x932 | 355x391 | 355x391 | どちらも337 |
| 375x667 | 174x192 | 170x187 | 311 / 315 |

**ホーム側の余白・カセット・`AVATAR_RATIO`・黒帯の中身を触ったら、ここも
測り直すこと。** 一幕とホームで
`document.querySelector('canvas').getBoundingClientRect()` を突き合わせるのが
いちばん早いです。

### 歩きはその場で足踏みさせる（`Avatar3D` の `stripTravel`）

`walk` には**前進が焼き込まれています**。Rootの位置が2.4秒で1.12ユニット動き、
しかも先頭が `-0.98` なので、**再生した瞬間にキャラが真横へ1ユニットずれます**。
枠（`GLView` の canvas）はキャラより少し広いだけなので、はみ出したぶんが
canvas の端でスパッと切れます。「出てくるとき右が切れる」の正体はこれでした。

移動は画面側（枠ごと `translateX`）が受け持つので、読み込み時に **Rootの位置の
track だけ落とします**。足の運びと腰の上下は別のボーンなので残り、歩き方は
変わりません。落とすのは振れ幅が0.3ユニットを超えるものだけで、`sensei.glb`
では `walk`（1.117）だけが該当します。次に大きい `angry` でも0.188なので、
待機や芝居の数センチの揺れは残ります。

**新しいモーションやアバターを足したときも自動で効きます。** 判定を変えたく
なったら `Avatar3D.tsx` の `TRAVEL` を見てください。

### 押すところは画面のいちばん上に重ねる

`Pressable` を下に敷くと、**相棒の上を押したときに `GLView` の canvas が
先に受け取ってしまいます**（親の `pointerEvents="none"` が canvas まで効かない）。
この画面には押すものが他に無いので、全面を1枚の `Pressable` で覆っています。

### 行き先を決めるのは1か所だけ

**この画面も職種の画面も `router` を触りません。** `_layout.tsx` の `OnboardingGate` が
`seenIntro` を見て寄越し、見終わってフラグが立つと同じ振り分けがホームへ返します。

職種の画面から直接 `router.replace('/intro')` してはいけません。`setRole` で state が
変わると `OnboardingGate` の「オンボーディングが終わっていたらホームへ」も同時に走るので、
**どちらが後になるかで行き先が変わります**（`/intro` が一瞬映ってホームに飛ぶ）。

### 歩きは2段で止める

等速で歩いてきて（`Easing.linear` 900ms）、最後のひと足だけ減速します（`Easing.out` 420ms）。
1本の減速カーブで通すと、最初から足を引きずって見えます。

### 向きは `Avatar3D.face(yaw)` に任せる

`face()` は**すぐには向きません**。描画ループが毎フレーム少しずつ寄せるので、
呼ぶのは「左を向け」「正面を向け」の1回ずつで済みます。一気に代入すると、
歩きながらパッと反転して人形に見えます。

**読み込みが終わる前に呼んでおくこと。** モデルが出てきた瞬間の向きに使われるので、
出てから回すと「正面を向いたまま横に滑る」絵になります。

### 歩き出す合図は `onReady`、ただし保険を置く

GLBを読み終える前に歩かせると、出てきたときには歩き終わっています。なので `onReady` を
待ちますが、**3Dモデルの無い相棒と読み込み失敗では `onReady` が来ません**。
3.5秒で歩き出す保険を置いて、ここで詰まらせないようにしてあります。

## チュートリアル（先生がアプリを案内する）

職種を選び終えると、選んだ先生が6歩でアプリを案内します（`src/store/tutorial.tsx`）。
実際にその画面へ移動し、**該当するタブを黄色いリングで光らせながら**説明します。

### タブを光らせる方法

**タブボタンの座標は測りません。** expo-router の `Tabs` からボタンの位置を取るのは
素直でなく、端末や安全領域で狂います。代わりに「いまどのタブが光る番か」だけを配り、
`TabIcon` が自分の名前と見比べて**自分でリングを描きます**。座標の計算がまるごと要りません。

描くときの順番に注意すること。

- リングは**いちばん最後に描く**。先に描くと、選択中の赤い丸ベタに塗りつぶされて消える
  （Webでは position:absolute の兄弟が後勝ちで上に来る）。`zIndex: 2` も要る
- 出しっぱなしのリング＋広がって消えるリングの2枚重ね。**広がるだけだと、
  消えている時間のほうが長くて見落とす**
- 広がるほうの倍率は控えめに。タブバーに切られることがある

### 吹き出しに3Dアバターを置いていない理由

先生の顔を出したいところですが、`GLView` をもう1つ立てるとホームのアバターと2重に
なります。読み込み直しも起きえて、非力な端末では効きます。ホームの回では**本物の
アバターが後ろに立っている**ので、吹き出しはアイコンと名前だけにしてあります。

吹き出しは `(tabs)/_layout.tsx` に住んでいます（タブの外に置くと、タブを切り替える
たびに消えるため）。下端の余白は `TAB.height + insets.bottom`。固定値にすると
ホームインジケーターのある端末で隠れます。

案内を見終えるか「とばす」を押すと `seenTutorial` を保存して、二度と出ません。
**記録のリセットでは出し直します**（アバターや職種も選び直すことになるので）。

## 本物のAIに渡す回（`ai-prompt`）

「AIリテラシーを教えるアプリ」なのに、**本物のAIを触った経験がほぼ無いまま修了できて
いました**（17本中1本だけ）。プロンプト道場・事故らないAI・これからのAIに1本ずつ足して、
4本にしてあります。

| exerciseId | レッスン | 何を書かせるか |
|---|---|---|
| `prompt-basics` | prompt-1 | 文章を書き直させる指示 |
| `prompt-role` | prompt-3 | 役割を与えて弱点を洗い出させる指示 |
| `risk-redact` | risk-1 | 実名や実数を伏せて相談する指示 |
| `rag-brief` | next-2 | 渡した資料の中からだけ答えさせる指示 |

**通せんぼをするのは `token-budget` だけ**で、`ai-prompt` は点が届かなくても先へ進めます
（AIの判断で揺れるもので止めない）。打つのが面倒な人が詰まらないための線引きです。

`exerciseId` は**アプリとサイトの両方に足すこと**。お題の中身はサーバー側
（`src/app/api/academy/grade/route.ts` の `EXERCISES`）が持っています。アプリから渡すのは
IDだけです——中身を持たせると、そこを書き換えてAPIキーにタダ乗りされます。
片方だけに足すと、黙って fallback（AIなしの簡易採点）に落ちます。

## 持ち帰り（`/sheet`）

17本終えても、手元に残るのは称号だけでした。「今日から使う3枚」というレッスンが
あるのに、**その3枚を保存する場所がどこにも無い。** 学んだことが端末の中の進捗
フラグにしかならないのは、実務のアプリとしておかしい。

まなぶタブのいちばん下から開けます。集めるのは**自分にしか出ていないもの**だけ——
「あなたの現場だと」（`roleNote`）と、職種別のプロンプト（`promptByRole`）です。
共通の解説は集めません（それはレッスンを読み返せば済む）。

- **終えた回のぶんだけ**増えます。全部を最初から見せると、ここを読めば済むことに
  なってレッスンが要らなくなります
- **まるごとコピー**できます。スマホで読み返すためのものではなく、仕事の場所へ
  持っていくものなので、貼る先を選ばないプレーンテキストで出します

## 用語は、本文の中から引ける

本文には「トークン」「RAG」「プロンプトインジェクション」が普通に出てきます。
初出の回では説明していますが、**あとの回で出てきたときに戻る手段がありませんでした。**
読み飛ばした人と、順番どおりに進まなかった人がそこで置いていかれます。

`src/data/terms.ts` にある語が本文に出てきたら、`TermText` が自動で押せるようにします
（`components/term-text.tsx`）。押すとその場に短い説明が出ます。

- **リンクはその本文の中で最初の1回だけ。** 同じ語が3回出るたびに下線が引かれると、
  本文が下線だらけでかえって読めません。伝えたいのは「ここは押せる」という事実だけ
- **長い語から当てます。** 「AIエージェント」と「エージェント」のように片方が
  もう片方を含むものがあり、短いほうから当てると長いほうが二度と出てきません
- 説明は**その場で足りる2〜3行**だけ。詳しい話はサイトの用語集
  （comixai.dev/glossary）へ渡します。**同じ文章を持ってきません**——持ってくると
  レッスン本文と用語集の二重管理になります
- シートは根元に1枚だけ（`TermSheetProvider` を `app/_layout.tsx` に置く）。
  本文のあちこちに `Modal` を置くと、そのぶん窓が増えます

**データの文字列にマークダウンは書かないこと。** 本文は素の `Text` で描くので、
`**強調**` と書くとアスタリスクがそのまま画面に出ます（一度やって直しました）。

## 「あなたの現場だと」（職種別の1枚）

オンボーディングで「選んだ職種にあわせて例とプロンプトが変わります」と約束して
いるのに、**書き分けは78カード中16か所しかありませんでした。** 8割のカードは誰が
選んでも同じで、約束と実体が合っていません。

そこで**全17レッスンに1枚ずつ**、その職種の現場に落とした話を置いています
（`Lesson.roleNote`）。9職種×17本＝153本。これで職種で変わる箇所は33に増えました。

- カードの配列には混ぜず、`lessonCards()`（`data/courses/index.ts`）が**読み終わりに
  1枚足します**。配列に混ぜると、レッスンごとに枚数が変わって進み具合の点がずれます
- 「あてはまらない」を選んだ人には `roleNote` が無いので、**そもそもカードが出ません**。
  共通文だけが出るのが正しい挙動です
- カードのセリフは職種に触れません。触れると `roleNote` と同じことを二度言うことになります

## レベルデザイン（バッジ・称号・1日の単位）

### 最上位の称号は「全部」に置く

一度は16（＝1日で取り切れる上限）に置いていましたが、**全20個のうち16で
マスターは軽すぎる**という判断で「全部」に戻しました。連続日数（3日・7日）と
復習の卒業（日をまたいで3回正解）が必須になるので、マスターは**どうしても
数日かかります**。それでいい——称号の頂点は、駆け抜けた人ではなく通い続けた
人のもの。急いだ人には16個目以降の「あと4つ」が、続ける理由として残ります。

| 称号 | 必要バッジ |
|---|---|
| AI見習い / 研修生 / 相棒 | 0 / 3 / 6 |
| AI使い / 職人 / 師範 | 9 / 12 / 15 |
| AIマスター | 20（＝全部） |

**バッジを増やすときは、この数字も見直すこと。** 増やしたぶん最上位が相対的に
緩くなります（分母だけ増えて分子が据え置きになる）。

### 作った仕組みには、報酬を付ける

★も復習も、遊びとしては作ったのにバッジが1つもありませんでした。やったことが
台帳に載らないと、やる理由が育ちません。足したのは6つ:
`star-first` / `star-5` / `star-all` / `review-first` / `review-10` / `perfect-all`。

これで**10本目あたりの無報酬地帯**（もとは開始5分で4個入り、そのあとが空だった）が
埋まり、同時に `star-all` と `perfect-all` が**ヘビーユーザー向けの上澄み**になります。

**「全★3」の分母に、★の付かないゲームを入れないこと。** トークナイザーと
トークン収めには★が付かないので、全レッスン数を分母にすると**永久に達成できない
条件**になります（分母は `SCORED_GAME_KEYS` が返す）。

**成績の鍵は「1レッスン1ゲーム」とは限りません。** prompt-3 / risk-1 / next-2 は
★付きゲームが2つあるので、鍵は `レッスンID:種類` になります（`gameKeyOf`）。
レッスンIDのまま相乗りさせると、片方を遊んだだけでもう片方の入口が
「もう一度あそぶ」になります（実機で報告のあったバグ）。

### コースの推奨順（ロックはしない）

5つのコースがいつでも開けるので、`basics-1`（トークンの話）を飛ばして `next-2`（RAG）に
行くと確実に迷子になります。`Course.needs` に前提コースを書くと、まなぶタブが
**開ける前に「先にこれ」と言います**。鍵はかけません——知っている人まで足止めするので。

### 1日という単位

「1日1本で十分だ」と先生が言うのに、**今日やったかどうかの表示も、今日ぶんを
終えた締めも無い**状態でした。連続日数だけが裏で数えられていた。

いまはホームのカセットが、今日ぶんを終えると「今日のぶんは終わり」に変わります
（`useToday`）。**黄色いピルも外します**——「次にやること」の印なので、
出したままだとまだ残っているように見えます。

### 修了試験と花火（`/exam/[courseId]` / `components/course-clear.tsx`）

コースを終えても、修了はバッジ1個で静かに流れていくだけで「1章クリアした」という
実感がどこにも無い、という指摘（実機）から作りました。

- 全レッスンを終えたコースだけ受けられる。**まなぶタブの各コースの末尾**と、
  最後のレッスンの結果画面（COURSE CLEAR のコマ）に入口がある
- コース全体から**10問をシャッフルして出題**（持ち問題が10未満なら全問）。
  8割正解で合格。落ちても何度でも受け直せる
- 間違えた問題は本編と同じく**復習に積まれる**（`answerQuiz` を通す）
- 合格の瞬間に**花火の全画面**（`course-clear.tsx`）。称号ランクアップより上の、
  アプリでいちばん派手な演出。夜空に花火が上がり続ける中で
  COURSE CLEAR → 章の名前 → 成績 → 先生のひとことが組み上がる
- 合格記録は `ProgressState.exams`（コースID → 時刻）。**関所ではない**——
  合格しなくても次のコースへは進める

### ミニゲームは全部、通らないと先へ進めない

もとは token-budget だけが必須で、他のゲームは素通りできました。すると
「やってもやらなくてもクリアになる」ので遊ばれず、読むだけで修了が積み上がる
（実機で指摘）。いまは**体験カード全部が修了の条件**です（合否の無い
トークナイザーは「わかった」まで見れば通る。ai-prompt はAIに繋がらないとき
簡易採点に降格するので、電波が無くても必ず抜けられる）。

### クイズの選択肢は、出すときに混ぜる（`components/quiz.tsx`）

データを書くと正解はつい2番目（B）に寄ります（実際、1章はほぼ全問Bで
「Bを押せば当たる」と気づかれた）。データ側を手で並べ直しても足すたびに戻るので、
**表示時に問題idから決まる順でシャッフル**しています。同じ問題はいつ開いても
同じ並び（毎回ランダムだと「前はCだった」という覚え方まで壊れる）。
`onPick` に渡るのはデータ上のインデックスなので、答え合わせ側は何も変わりません。

### エンディング（`/ending`）

入口には14コマの絵巻があるのに、出口は「全課程、修了」という小さなパネルだけでした。
全17本を終えると、通した本数・ノーミス・★3・復習で直した数・学習した日を並べた
締めが出ます。**終わりにはしません**——復習と★3集めは残るので、「ここから先は現場で」
と言って持ち帰りに渡します。ホームから何度でも見られます（1回しか見られない画面は、
撮ることもできない）。

## ガチャ（ガチャP・舞台テーマ・アバター）

学習の節目で「ガチャP」が貯まり、3Pで1回まわせます（`/gacha`）。

- **貯まりかた**：ログインボーナス+1（1日1回、ホームを開いたとき）／バッジ+1／
  称号が上がる+3／修了試験の初回合格+2。買えません。学びの副産物としてだけ貯まる
- **景品は2種類**（`src/data/gacha.ts` の `GACHA_POOL`）
  - **舞台テーマ**：ホームでキャラが立つ場所。**描けたものは専用の絵**を持ち
    （`StageTheme.art` に画像・比率・壁色の3つ組）、まだ描けていないものは
    素の教室に色を重ねる。飾り（雨・桜・雪・星・火の粉）は
    `components/stage-effect.tsx`。ループアニメは置かない——常駐画面で電池を
    食うので、置き方で「降っている感じ」を出す
  - **アバター**：先生の色違い（金髪・銀髪・桃色・緋色）を**独立した1体**として
    当てる。**選べるアバターがガチャで増えていく**建て付けで、キャラ本体の
    モデルができたらそれもプールに足す。GLBは共通で、テクスチャの差し替えだけで
    成立する（`data/avatars.ts` の `SKINS`）。使うと、ホームだけでなく
    **レッスンも試験も全画面**その体になる（性格・セリフはベースのキャラのまま）
- **ダブりは+1P返す**。プールが小さいので、返さないと後半のハズレ感が強すぎる
- **既存ユーザーへの遡及**：あとから入れた仕組みなので、初回移行時にバッジ数と称号から
  換算してPを配る（`progress.tsx` の読み込み処理）
- アバターと舞台の変更は、ガチャのコレクション欄からも**せってい**からもできる。
  せってい・コレクションとも**持っている体だけが並び、当てるたびにリストが伸びる**

マシンは画像を使わず、太い黒枠＋ベタ影のViewで描いてある（`app/gacha.tsx`）。
ダイヤル回転→揺れ→カプセルが弾んで落ちる→タップで開封、の段取り。

### 舞台の見本（確認用）

舞台はガチャの景品なので、当てるまで見られない。**作った絵が実機でどう見えるかを
確かめる手段が無かった**ので、`/stages` に20枚を並べた画面を置いてある
（せってい →「確認用 20枚ぜんぶ見る」）。押すとその場で飾れる。

**持ち物は増やさない。** `previewTheme()` が装備中のIDを差し替えるだけなので、
コレクションの数（n/20）もガチャの引きどころも変わらない。
`setTheme()` は持っていないテーマを弾く作りのまま触っていない。

確認用の画面なので、**公開前にせっていの入口ごと外すか、隠しの操作に付け替える**こと。

### レア度は光の量で見せる

舞台を20枚（N10/R7/SR3）に増やしていく計画で、**レア度が見た目で分かる**ように
軸を決めてある。Nは曇り・蛍光灯・低彩度でわざと地味に、Rは夕日や炎など光そのものが
主役、SRは光条・鏡面・金。プロンプトと描き分けは `assets/images/_raw/README.md`。

**キラキラは絵に描き込まない。** 背景を派手にするとキャラ（黒スーツ・輪郭線なし）が
溶けるので、絵は光を奥と上に集めて立ち位置を中間トーンに保ち、
**粒と縁の光はアプリ側で足す**（`components/stage-effect.tsx`）。

#### 飾りは舞台ごとに動きを変える

| 舞台 | 動き |
|---|---|
| サーバーの聖堂 | `streaks` 線状の光が下から上へ走る |
| 雲海の上の教室 | `pika` その場でチカチカ瞬く。大きい粒には光条（十字のフレア） |
| 金インクの原稿の中 | `burst` 中央から手前へ放射状に、出ては消える |

**同じ動きを色替えで配らない。** 最初は3つとも「粒がゆっくり流れる」で色だけ
変えていたが、当てた側からすると同じものが3回出てくるのと変わらない。

**アイコンの星や塗りの四角は使わない。** 写真のような絵の上では漫画記号として
浮き、幼く見える。使うのは中心が明るくすぐ外で消える円と、両端が消える線だけ。

**明るい絵の上では明るい粒が飛ぶ。** 雲海と金インクは紙・空が白いので、
濃い金の粒を半分混ぜてある。それでも沈むときは光条を足すと「光っている」と読める。

##### 動かしかたで踏んだ穴

- **またたきを層まるごとの不透明度でやると、絵が薄くなって消えていくように
  見える**（層が一斉に暗くなるため）。小さな組に分けて、組ごとに違う周期・
  違う出だしで光らせる
- **山を鋭く尖らせると、光っている時間が周期の1割しかない。** 組をいくつ
  用意しても同時に光るのは1組で、画面はほぼ消えて見える。山は広く谷は浅く
- **1周は長く取る（60秒）。** 短い周期で回すと、1周の終わりから次の始まりへ
  移るところで1〜2フレーム止まる。5.5秒ごとに線がカクッと引っかかって見えた。
  **1周を60秒にして、その中で何度も折り返す**——折り返しは `interpolate` の表の
  中でやるので値が飛ぶだけで間が空かない。継ぎ目は60秒に1回まで減り、しかも
  その瞬間の値は周の始まりと同じになるよう作ってあるので目に見えない。
  **粒の数も要素の数も変わらないので、これで重くはならない**
- **`Animated.loop` は各周で「開始時の値」まで戻す。** 終端で止めると以降は
  1→1 のアニメになり、二度と動かない。再開のたびに0へ戻す
- **こちらから止めてはいけない。** 電池を気にして「背面に回ったら止める」を
  入れたら、**一度画面を離れると二度と動かなくなった**。Webでは
  `useNativeDriver` が効かず rAF 駆動になり（起動ログにも出る）、iOSの
  ホーム画面アプリは背面から戻ったときの通知が来ないことがある。止めた側だけが
  残って再開しない。**ブラウザは見えていないあいだ rAF を自分で止める**ので、
  そもそも止める必要が無かった
- **自己修復の見張りは置かない。** 一度「値が進んでいなければ回し直す」を
  入れたが、誤判定のたびに全部が0へ飛ぶので、線がガクッと戻って見えた。
  判定を厳しくしても誤りは0にならないし、そもそも**永久に止まる原因は
  こちらの stop() だけ**で、それを外した時点で無くなっている。
  ブラウザが止めた rAF はブラウザが戻す
- 回し直すとき（アプリ復帰時）は**出だしのずれも作り直す**。波を何本も
  ずらして重ねているものを一斉に0へ戻すと、ずれが消えて同時に光る
- **飛ばす距離はコマの大きさに合わせる。** 外へ振りすぎると粒がすぐ画面の
  外へ出て、見えている時間がほとんど無くなる（噴き出しているのに何も
  起きていないように見えた）
- **またたきの拡大縮小は浅く。** 大きく動かすと組ごと寄り引きして見え、
  瞬きではなく「画面が伸び縮みしている」ように読める

値は Animated.Value を数本だけ。中身は静止したまままとめて動かす（粒の数だけ
アニメを持たせない）。移動・拡大・不透明度だけなので `useNativeDriver` が効く。

**粒と縁の光はアプリ側で足す**（`components/stage-effect.tsx`）。

#### 飾りは「写真に写る光」に寄せる

最初はアイコンの星と塗りの四角を散らしていたが、**写真のような絵の上では
それだけが漫画記号として浮き、幼く見えた**。玉ボケ・空気中の塵・レンズを
横切る光に作り替えてある。決まりは、小さく／大きいものは薄く／輪郭を作らない。

**動かす。** 層ごとに `Animated.Value` を1つだけ持ち、中身は静止したまま層ごと
流す（粒の数だけアニメを持たせない）。移動と不透明度だけなので
`useNativeDriver` が効き、JS側は毎フレーム何もしない。継ぎ目は、粒を上下
2枚ぶん敷いて1枚ぶん動かすことで消している。速さの違う層を重ねると奥行きが出る。
**アプリが背面に回ったら `AppState` で止める**（常駐画面なので）。

**きらきらは「細かく・くっきり・数多く」で出す。** 粒を大きく薄くすると、
画面が霞んで「モサッ」とする。芯をはっきり作って、そのすぐ外で消す
（放射グラデーションの止め位置）。1層あたり30〜40粒を、層ごとに違う速さで流す。

**またたきは層ごと**。粒ひとつずつにアニメを持たせず、層の明るさを上下させる。
層の速さがそれぞれ違うので、重なると粒が個別に瞬いて見える。

濃さ・速さ・数・またたきの回数は `SPEC` の表1か所。金箔（`kinpaku`）だけ
5層＋横切る光で、これがいちばん豪華な飾り＝目玉の1枚用。
**明るい絵の上では明るい粒が飛ぶ**ので、濃い金の層を1枚かませてある。

▍止めたループを再開するときは値を0に戻す
`Animated.loop` は各周で開始時の値まで戻すので、**終端で止めるとその後は
1→1 のアニメになり、二度と動かない**。画面を行き来したあとに止まって
見えたのはこれだった。
アバターを当てたときは、開封カードに**その色の先生本人（3D）**が出る。

### 色違いテクスチャの作りかた

`node tools/recolor-sensei.mjs` が `sensei-texture.jpg` から
`sensei-<id>-texture.jpg` を生成します。髪だけを塗り替える方法
（GLBの頂点から起こす頭マスク×彩度の2段構え）はツールの冒頭コメントに。
新しい色は `VARIANTS` に1行足して実行 → `avatars.ts` の `SKINS` に登録。
アバター本体（相棒たち）の3Dモデルが増えたら `gacha.ts` のプールに足す設計。

## 復習（間違えた問題が、日を置いて戻ってくる）

読んで1問答えて終わり、では**間違えたことに気づいて終わる**だけで、直る機会が
どこにもありませんでした。先生は「間違えたところは、あとで戻ればいい」と言うのに、
戻る手段がレッスンのやり直ししか無かった。そこを作り直したのがこれです。

- クイズは**1レッスン3問**（全17本で51問）。1問では当てずっぽうと区別がつきません
- 間違えた問題だけが控えに入り、**翌日 → 3日後 → 7日後**と間隔をあけて戻ってくる
- 3回続けて正解したら卒業（もう出ない）。途中で間違えたら連続はゼロに戻る
- ホームは「はじめる」の**横**に「復習 n」、まなぶタブは一覧の先頭に出る

### 控えるのは「間違えた問題」だけ

全問を反復すると、覚えている問題まで毎日出てきて続きません。**一度も間違えなかった
問題は記録すら作りません**（`answerQuiz` が `if (!prev && correct) return` で抜ける）。

### 出す問題は、記録を読み終えてから写す

`review.tsx` は開いたときの並びを1回だけ写して、そのあと動かしません
（答えるたびに `useReview` が引き直されるので、繋いだままだと**正解した瞬間に
その問題が消えて画面が飛ぶ**）。

写すのは `ready`（AsyncStorage を読み終えたか）が立ってからです。`useState` の
初期値で取ると、**記録がまだ空の1回目の描画で写してしまい、いつ開いても
「直すものは無い」になります**。この画面を直接ひらいたときに実際そうなっていました。

### 卒業は日をまたいで3回

その場で3連打しても卒業できない、が狙いです。覚えたつもりを卒業させないため。
期限前のものは「まなぶ」から前倒しで解けますが、**前倒しでも間隔は伸びます**。
急いで潰したい人の道は塞ぎません。

### `QuizItem.id` は変えない

復習の記録はこのidで引きます。**idを変えると、その人の「まだ直っていない問題」が
行方不明になります。** 問題文を直すのは構いませんが、idはそのまま。差し替えたい
ときは新しいidにしてください。`${レッスンid}-q${通し番号}` で付けています。

順番から自動で作っていないのは、あいだに1問足した瞬間に**それ以降の全部の履歴が
ずれる**からです。`ALL_QUIZ`（`data/courses/index.ts`）が読み込み時にidの重複を
検査して、重複していれば起動時に落とします（黙って混ざるほうが厄介なため）。

### ホームは行を増やさない

ホームは1画面に収める作りなので、カセットに行を足すと**そのぶんアバターが縮みます**。
復習の入口は「はじめる」と**同じ行に横並び**で置いてあります。まなぶタブは
スクロールするので、あちらは普通にカセットを1枚足しています。

## ミニゲームの成績（★とミス）

作ったときは、ゲームごとに合否の考え方がばらばらでした。

| | 元の状態 |
|---|---|
| 仕分け | ミス1回まで（**負けられる**） |
| 詰める | 完全一致しないと「決める」ボタンすら出ない（いちばん厳しい） |
| 組み立て | 何を選んでも必ずCLEAR（**負けられない**） |
| 見つける | ミスを数えるだけで、外しても通る |
| 並べる | 間違えても札が消えないので、総当たりで必ず解ける |

同じ「MINI GAME」の看板で難度が3段階違い、しかもプレイヤーには見えない。
**半分は押せば終わる**ので、CLEARのスタンプまで軽くなっていました。

そろえたのは2つだけです（`components/games/score.ts`）。

1. **どのゲームにも「外す」がある** — `allow` 回まで許して、超えたら `TryAgain`
2. **成績が★で残る** — ミス0で★3／1で★2／それ以上で★1。自己ベストを持つ

### タイムは測るが、★には使わない

急かすと、考えずに当てにいく遊びになります。**記録としてだけ**クリア画面に出します。

### 難度は始める前に言う

タイトル画面と入口カードに「ミスは○回まで」を出します。見えていないと、
厳しいほうが理不尽に感じるだけです。

### 組み立ては「弱い札」に印を付ける

`BuildSlot.options[].weak` です。**「いちばん良い札」ではなく「弱い札」**なのは、
良い選び方が1つとは限らないから。基本の回では「同僚向け」でも「取引先向け」でも
正解で、まずいのは「（指定しない）」だけです。

外れの札も**押せます**。押して結果を読むのがこの体験の中身なので、触って比べてから
決められます。ミスになるのは決めた瞬間だけ。

### 自己ベストは入口に出す

出ていないと、もう一度やる理由が生まれません。★3未満なら、ボタンの文言も
「★3をねらう」に変わります。記録は `progress.games`（レッスンIDで引く）。
**同点は「更新」にしません**——毎回出ると、その言葉が軽くなります。

## 体験カード（ミニゲーム）

レッスンは「コマを送って読む → クイズ」が骨ですが、**読み物にしないための
仕掛け**として体験カードを挟みます。**17本すべてに入っています。**

| 種類 | 何をする | 入っているレッスン |
|---|---|---|
| `sort` | 流れてくる1枚を左右の箱に振り分ける | basics-3 / prompt-4 / risk-1 / next-1 / next-3 |
| `find` | 文書の危ない行をタップして摘発する | risk-2 / risk-3 |
| `build` | 部品を選ぶと出力がその場で変わる | basics-2 / prompt-2 / prompt-3 |
| `order` | 工程を正しい順に並べる | work-1 / work-2 / work-3 |
| `fit` | 限られた広さに、要る資料だけ載せる | basics-4 / next-2 |
| `tokenizer` | 好きに打って、トークンの割れ方を見る | basics-1 |
| `token-budget` | 決められたトークン数に収める | basics-1 |
| `ai-prompt` | 本物のAIに指示を渡して採点される | prompt-1 |

### 出題順・選択肢は毎回シャッフル

データに書いた順のまま出すと、答えが並び順で覚えられてしまう
（仕分けは左右交互、詰めるは上の3つが正解、と実機で見抜かれた）。
仕分けの札・詰めるの資料・並べるの札・組み立ての選択肢は、
遊ぶたびに `shuffled()`（`games/score.ts`）で並び替える。

### ゲームの持ち色と掛け声

- 各ゲームは**持ち色**を持つ（`GAME` の `color`）。タイトルの紋章・
  上の帯の下線・小型アイコンに使い、どのゲームにいるかが色で分かる。
  黒地のゲームは紙の側と別世界なので、色数が多くてよい
- 正解のたびに指の近くで**掛け声**（ナイス！→さすが！）がぽんと出る
  （`games/parts.tsx` の `useCheer`）。連続で当てるほど言葉が強くなる。
  ループアニメは使わない（電池対策）

### 打たせるのは、ごく一部でいい

はじめは体験が3本しかなく、**その3本すべてがテキスト入力**でした。残り14本は
読んでクイズ1問だけ。スマホで長文を打つのはそれ自体が面倒なので、体験の入口が
そこにあると、そもそも入ってもらえません。

なので**指1本で成立するもの**（`sort` / `find` / `build` / `fit`）を軸にし、
打つのは `ai-prompt` の1本だけ残しました。本物のAIに渡す手ざわりは、それはそれで
価値があるためです。

問いの形が同じなら、**1つの仕掛けで何本も賄えます**。`sort` は「ウソ/ホント」
「入れていい/ダメ」「任せる/自分でやる」「スロップ/良質」の4本を1つで回しています。
新しいレッスンに体験を足すときも、**まず既存の4種で書けないかを考えてください。**

### わかりやすさのルール（ゲーム・画面を足すときの必須チェック）

実機テストで「これどういう意図？何したら正解？」が出た反省を、
ルールに落としたもの。**新しいゲーム・画面はこの7つを守ること。**
1つでも欠けると、作った側には自明でも、初見の人は推測で遊ぶことになる。

1. **名前は「〜しよう」**。「仕分け」は遊びの分類、「正しく仕分けよう」は
   自分への指示。名前だけで目的が立つ形にする（`mini-game.tsx` の `GAME`）。
2. **お題と正解条件は、画面に出ている間ずっと出す**。タイトル画面は
   数秒で消える前提で作る。読み飛ばした人が札と箱だけを前にしても
   迷わないこと（仕分けの `brief` 常時表示がこの形）。
3. **場面と仕組みは分けて書く**。お題（場面）はデータの `brief`、
   仕組みと合格条件（「あいまいな札のまま決めるとミス」）はコード側の
   固定文。データを増やすたびにルール説明を書き直させない。
4. **空白には「これから起きること」を書く**。打つ前・選ぶ前の黒い空きは、
   何が起きる場所なのか分からない（トークナイザーの「打つと、ここに〜」）。
5. **凡例は見る場所に置く**。直前のカードで説明した色や記号でも、
   ゲームの中でもう一度言う（チップの白／赤の凡例）。
6. **決める口・進む口は下の帯に固定**。本文の途中に置くと、回ごとに
   位置が変わって手が迷う（`GameFrame` / `Screen footer`）。
7. **選択肢の見た目で答えを誘導しない**。2択の箱の片方だけ黄色だと
   「押してほしいほう」に見える。当てさせる場面は重みを揃える。

### 足すとき

`src/data/types.ts` の `LessonInteractive` に型を足し、
`src/components/games/` に描き方を書き、`mini-game.tsx` の `GAME`（名前と遊び方）と
分岐に足します。合否のあるものは `onClear` を呼ぶこと（呼ばないと先に進めません）。
**上の「わかりやすさのルール」7つを通すこと。**

`sort` は `allow` 枚まで間違えても通します。1枚外して最初からやり直しだと、
考えるより当てにいくようになるためです。外した札は最後に理由付きで見せます。

`order` は**ドラッグさせません**。スマホの縦スクロールの中で長押しドラッグを
やらせると、触るたびに画面が動いて事故ります。「つぎにやること」を上から
押していく形にしてあり、押した順がそのまま並びになります。

### データが解けるかを確かめる

体験カードは**データを間違えると詰みます**。とくに `fit` は、`needed` な資料の
`cost` 合計が `capacity` を超えると**絶対に通れません**（画面上は普通に見える）。

追加・変更したら、次を確かめてください（画面を触らなくても分かります）。

- `fit` … 要るものの合計 ≦ 広さ。全部載せれば通る、にもなっていないか
- `sort` … 左右どちらの箱も使うか。`allow` が札の数以上になっていないか
- `find` … 当たり行が1つ以上あり、全部が当たりになっていないか
- `order` … `why` と `tooEarly` が全工程に書かれているか
- `build` … どの軸も選択肢が2つ以上あり、`result` が空でないか

## セリフを相棒ごとに書き分ける

フキダシの中身は**そのキャラがしゃべっている言葉**なので、相棒を変えたら
口調も変わります。仕組みは通してあり、**先生ぶんだけが埋まっている**状態です。

| セリフ | 置き場 | 書き分けの入れ物 |
|---|---|---|
| レッスンのカード | `src/data/courses/*.ts` | `sayByAvatar` |
| クイズ・結果 | `src/data/voice.ts` の `LESSON_VOICE` | `byAvatar` |
| ホームの小話 | `src/data/voice.ts` の `SMALL_TALK` | 相棒ごとに配列を丸ごと |
| 称号のひとこと | `src/data/badges.ts` の `TITLES` | `sayByAvatar` |
| チュートリアル | `src/store/tutorial.tsx` の `TUTORIAL` | `sayByAvatar` |

```ts
{ need: 3, name: 'AI研修生', say: '研修生に上げておく。まだ何も覚えてないが。',
  sayByAvatar: { senpai: 'お、研修生じゃん！いいね、その調子！' } },
```

**未記入なら共通（＝先生の言葉）にそのまま落ちます。** 1人あたり80本ほど
あるので、一度に書き切る前提にしていません。GLBを足した相棒から少しずつ
埋めていけます。口調の指針は `src/data/avatars.ts` の `personality`
（先輩＝テンション高め・タメ口／後輩＝敬語・素直／師匠＝老練・比喩多め／
相棒＝無感情・簡潔・数字で語る）。

レッスンのカードだけは職種別（`sayByRole`）とぶつかります。**相棒別が勝つ**
ので、「あんたの仕事は〜」と相手の仕事に触れる回に相棒別を書くときは、
仕事に触れない言い回しにするか、書かずに職種別へ譲ってください。

なお、**アプリがユーザーに話している説明文は敬語**で、キャラのセリフとは別物です
（そちらは相棒が変わっても変わりません）。

## アバターを追加する

台帳（`src/data/avatars.ts`）には先生のほかに4体分のエントリが**枠だけ**入っている。
`model: null` のあいだは選択画面に「準備中」と出るだけで選べないので、
GLBができた順に埋めていけばいい。

1. GLBを用意する。**アニメーション名は `src/avatar/motions.ts` の11種に揃える**
   （`laugh` / `wave` / `bow` / `idle-a` / `arms-crossed` / `walk` / `scared` / `angry` / `worried` / `idle-b` / `explain`）
2. スマホ向けに変換する

   ```bash
   node tools/transcode-avatar.mjs 元.glb assets/models/senpai.glb assets/models/senpai-texture.jpg
   ```

3. `src/data/avatars.ts` の該当エントリの `model` を埋める

   ```ts
   model: {
     glb: require('@/assets/models/senpai.glb'),
     texture: require('@/assets/models/senpai-texture.jpg'),
     view: STANDING,
   },
   ```

### なぜ変換が要るのか

サイトで使っている `public/claude-app/sensei.glb` は、そのままでは端末アプリで動かない。

| 元GLBの仕様 | 端末で困ること | 変換後 |
| --- | --- | --- |
| `EXT_meshopt_compression` | デコーダがWASM。HermesにWebAssemblyが無い | 展開して埋め込み |
| `EXT_texture_webp`（GLB埋め込み） | RNの画像デコーダを通せない | JPEGとして**GLBの外**に出し、実行時に `material.map` へ割り当て |
| 380,790トライアングル / 4096pxテクスチャ | スマホのリアルタイム描画には重い | 45,692トライアングル / 1024px |

結果、**3.9MB → GLB 1.9MB + テクスチャ 119KB**。
`tools/transcode-avatar.mjs` がこの3つをまとめてやる（`RATIO` / `TEX_SIZE` 環境変数で調整可）。

## レッスンを増やす

`src/data/courses/` に1ファイル1コース。`index.ts` の `COURSES` に足せば一覧・進捗・バッジ判定に自動で入る。

職種で内容を変えたいところは、共通のキーの隣に `〜ByRole` を書く：

```ts
{
  say: '最初は、失敗しても平気な仕事から渡せ。',
  sayByRole: { sales: 'いきなり顧客向けメールを書かせるな。' },
  body: '共通の本文',
  bodyByRole: { office: '事務職向けの本文' },
  promptByRole: { marketing: 'マーケ向けのコピペ用プロンプト' },
}
```

`ByRole` に無い職種は共通のものが使われるので、**書き忘れても壊れない**。

### 体験カード（読むだけにしない仕掛け）

カードに `interactive` を足すと、本文の下に道具が出ます。選択式のクイズだけだと
飽きるので、**手を動かす場所**をレッスンの中に挟むための仕組みです。

```ts
{
  say: '好きに打ってみろ。区切りが見えるはずだ。',
  heading: 'AIの目線で見てみる',
  body: '…',
  interactive: { kind: 'tokenizer', presets: ['こんにちは'] },
}
```

| kind | 中身 | 合否 |
|---|---|---|
| `tokenizer` | 打った文字がどうトークンに割れるか見る | なし |
| `token-budget` | 決めた範囲のトークン数に収める | **あり。通らないと次に進めない** |
| `ai-prompt` | 実際にAIに指示を出し、成果物と指示を採点してもらう | 点は出るが**進行は止めない** |

**先に進めなくするのは `token-budget` だけ。** トークン数は誰がやっても同じ答えに
なるので、止めても必ず抜けられます。`ai-prompt` の点はAIの判断で揺れるので、
**揺れるもので通せんぼをしません。**

合否のあるものは、条件を満たしたら `onDone(true)` を呼びます。レッスン側
（`src/app/lesson/[id].tsx`）がこれを見て「つぎへ」を出します。増やすときは
`src/data/types.ts` の `LessonInteractive` に足して、`src/components/lesson-interactive.tsx`
に描き方を書いてください。**体験は職種で出し分けません**（全職種共通の道具）。

#### トークナイザーについて

サイトの `/tokenizer` と同じ **cl100k_base** を使っています（`src/lib/tokenizer.ts`）。

- **BPEの表だけで約1MBある**ので、`import()` で遅延読み込みしている。
  Web版では別ファイルに分かれ、体験カードを開くまで落ちてこない
- `o200k_base` は2.2MBあるので採らない
- **日本語は1トークン＝1文字ではない。** UTF-8のバイト列をまとめる方式なので、
  1トークンだけをdecodeしても文字として成立しないことがある（置換文字になる）。
  表示は必ず `toChips()` を通し、**文字として読めるところまで束ねる**こと。
  赤いチップがその「束ねた塊」で、右の数字がトークン数

#### AI採点（`ai-prompt`）

書いたプロンプトを**実際にClaudeに渡して実行させ、その結果ごと採点**します。

```
アプリ  ──POST──▶  comixai.dev/api/academy/grade  ──▶  Claude Haiku
        ◀── {output, score, good, improve, missing}
```

**APIキーはアプリに置きません。** 鍵はサイト側（Vercelの環境変数
`ANTHROPIC_API_KEY`）にあり、**費用は吉川持ち**です。だからアプリが送るのは
`exerciseId` と書いた文だけで、**お題の中身（システムプロンプト）はサーバーが持ちます**。
アプリに持たせると、そこを書き換えて鍵にタダ乗りされます。

お題を増やすときは**2か所**に足すこと。片方だけだと fallback に落ちます。

1. アプリ: カードの `interactive.exerciseId`
2. サイト: `src/app/api/academy/grade/route.ts` の `EXERCISES`

##### 費用の歯止め

1リクエストあたり **0.5円ほど**（Haiku、出力700トークン上限）。歯止めは4段:

| 場所 | 中身 |
|---|---|
| `max_tokens` | 700。**ここがいちばん効く** |
| 入力 | 600字まで |
| IPごと | 10分に12回 |
| 全体 | 1日 `ACADEMY_DAILY_MAX`（既定1500 ≒ 750円/日） |

ただし**カウンタはインスタンス内メモリなので、Vercelでは複数インスタンスに
分かれてすり抜けます。** 事故（連打・ループ）を止める一次防波堤であって、
本当の歯止めにはなりません。**Anthropicのコンソールで月額の上限を掛けてください。**
そこだけが確実な天井です。

##### 繋がらないときは簡易採点に落ちる

鍵が無い・上限に達した・通信できない——どの場合も `fallback: true` が返り、
アプリは**AIなしの簡易採点**（役割・目的・条件・出力形式の4語があるかを見るだけ）
に降格します。点も合否も出るので、**学習は止まりません**。この降格を壊さないこと。

#### 課題の範囲の決め方

`token-budget` の `min`/`max` は、**自然に書いた答えが上限を少し超える**あたりに置きます。
日本語は1文字≒1トークン前後なので、`20〜35` なら30〜40字ぶん。狭すぎると
削るだけの作業になり、広すぎると何も学ばずに通ってしまいます。

### 職種を増やすとき

1. `src/data/types.ts` の `RoleId` に足す
2. `src/data/roles.ts` に1件足す（アイコン・名前・キャッチ・当てはまる人3つ）
3. `src/data/courses/` の **`〜ByRole` 全16か所**にその職種の文章を書く
   （`basics.ts` 1・`prompt.ts` 6・`work.ts` 9）
4. サイトの `src/app/guide/data.tsx` にも同じ slug でガイドを足す。
   ヒーロー画像は `docs/guide-hero-prompts.md` を見ること

`ByRole` を埋めなくても落ちませんが、**「職種別」の札を出しておいて中身が共通のまま**
というのがいちばん白けます。書けないなら職種を足さないほうがましです。

書き漏らしはこれで見つかります。

```bash
python3 - <<'PY'
import re, pathlib
ROLES = ['sales','marketing','office','creator','hr','support','planner','owner','it']
for f in sorted(pathlib.Path("src/data/courses").glob("*.ts")):
    src = f.read_text()
    for m in re.finditer(r'(\w+ByRole):\s*\{', src):
        i, depth = m.end(), 1
        while depth:
            depth += {'{': 1, '}': -1}.get(src[i], 0); i += 1
        keys = re.findall(r'^\s{12}(\w+):', src[m.end():i], re.M)
        miss = [r for r in ROLES if r not in keys]
        if miss:
            print(f"{f.name}:{src[:m.start()].count(chr(10))+1} {m.group(1)} 欠け={miss}")
PY
```

なお `'other'`（あてはまらない）は**わざと byRole を持ちません**。共通文がそのまま出るのが
正しい挙動なので、上のチェックの `ROLES` にも入れないこと。画面側は `role.generic` を見て
「◯◯向けで表示中」ではなく「共通の内容で表示中」と出し分けています。

コースを増やしたら `src/data/badges.ts` に修了バッジを1件足すこと（`Course.badgeId` と同じID）。
バッジの判定条件は `src/store/progress.tsx` の `evaluateBadges()` に集約してある。
